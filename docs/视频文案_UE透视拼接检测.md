# 《UE，用 C++ 还原鬼泣5/异环中的透视拼接检测》口播文案

先看结果。

一颗星被拆成两半，一半贴在柱子上，另一半贴在后面的墙上。平时看它们是错开的。走到指定位置后，两块在视野里拼起来，图案开始发光；保持两秒，门打开。

这里我不做屏幕截图比对，也不判断贴图本身长什么样。检测只看相机和碎片之间的几何关系。

标定时，先确定一个观察点。这个点通常放在地面上的 Manager 位置，再加上相机高度。对每个碎片，保存两项数据：从观察点到碎片的方向，以及距离。

运行时，每零点一秒拿一次玩家相机位置。对每个碎片重新算方向和距离，然后和标定值比较。

方向比较用点积。点积比较的不是两个物体，而是两条从观察点指向同一个碎片的方向：一条来自标定点，一条来自玩家当前相机位置。两条方向相同，点积接近 1；方位偏得越多，点积越小。

距离比较直接取绝对差。只比距离不够：标定点前方五米和左侧五米，到某个碎片的距离可能一样，观察角度却完全不同。所以位置判定同时需要方向和距离。

每个碎片独立比较。方向点积达到阈值、距离差在容差内，这个碎片就算通过。最后算通过率。碎片深度和方位拉得越开，玩家站偏一点时越容易有碎片不通过，位置就锁得更紧。

这个版本一开始有个问题：位置检测只读相机位置。玩家站对位置以后，即使低头看地，位置关系还是对的，仍然会触发。

所以又加了一层视线检测。这次读的是相机朝向，不是相机位置。标定时先计算“标定点指向图案中心”的方向；运行时拿相机前向向量和它做点积。相机朝向图案中心，视线通过；低头或转头，点积下降，进度停住。

图案中心取的是所有碎片位置的平均值。多个碎片不可能同时逐个对准，但玩家应该看向它们拼合后的中心。

位置和视线都通过后，开始累积时间。这个项目设为两秒。中途移动或转头，进度清零。这个进度同时用来驱动发光强度，所以玩家能看到图案逐渐亮起来。

图案显示本身比较简单。同一张贴图通过 UV 缩放和偏移切出上半和下半，分别做成材质实例，再赋给不同 Decal。碎片的视觉对齐仍然需要手动摆，这是场景设计的一部分。

发光放在 EmissiveColor，不放在 BaseColor。后者会把颜色推白；前者配合 Bloom 才有光晕。C++ 只在运行时给动态材质实例写一个 `GlowIntensity` 参数。

整套逻辑可以概括成：标定每个碎片的方向和距离，运行时做位置比较；再单独检查相机是否看向图案中心；最后要求持续保持。它不验证画面上的像素级拼合，但对固定关卡里的透视谜题足够直接，也方便调参。
