## 1. 这个谜题是什么

**最终效果**：一个完整的图案（五角星 + 圆环）被拆成上下两半，分别贴在场景中前后不同位置的柱子和墙上。玩家走到某个**特定位置**、朝某个**特定方向**看过去时，上下两半在视野里"拼接"成完整图案，此时图案开始**发光增强**，持续对准 **2 秒**后判定解密成功，触发**门打开**。

**关键点**：
- 碎片**不在同一平面**上（有前后深度差），只有玩家处于标定过的那个视角，碎片才会视觉对齐。
- 靠的是**透视原理**（越远看起来越小、角度越斜），不是简单的平面移动。
- 玩家**必须看向图案**（防低头作弊），且要**持续保持 2 秒**（防一晃而过）。

## 2. 核心原理：为什么"透视"能拼成图

### 2.1 视差与透视

想象两块拼图碎片：
- 一个**近**（比如柱子上），一个**远**（比如后面的墙上）。
- 你从正前方看：它们排成一条线，拼成完整图案。
- 你往**左**挪一步：近的那块在你视野里往右移得多，远的那块移得少，两块就**错开了**，图案散架。
- 你**后退/前进**：两块的大小比例变化，也错开。

这就是**视差**（Parallax）——不同深度的物体，随观察者移动而相对位移不同。透视拼接谜题就是把碎片放在不同深度，**锁定唯一一个能让它们拼合的视角**。

### 2.2 三种检测方案（我们怎么选的）

| 方案 | 思路 | 结论 |
|---|---|---|
| A. 屏幕投影 | 把碎片投影到屏幕上，算它们拼合的"正确屏幕位置"，玩家相机接近即触发 | 计算复杂、依赖视口，弃 |
| B. 投影聚光灯 | 用灯把图案"照"到墙上 | 像投影仪，不是我们要的"贴画/拼图"，弃 |
| C. **点积 + 距离比对**（采用） | 标定时记录"每个碎片相对玩家位置的方向和距离"，运行时比对相机是否在同样位置 | 简单、稳定、够用 ✅ |

**方案 C 为什么够用**：拼图只要求玩家站在"和标定时一样的位置、朝一样的方向"。方向用**点积**（两向量夹角的余弦）判断，距离用**绝对值差**判断，两个都通过就算对齐。不需要复杂的屏幕投影数学。

### 2.3 点积（Dot）是什么

两个单位向量的点积 = 夹角的余弦值：
- 方向完全一致 → 点积 = 1
- 偏差 5° → 点积 ≈ 0.996
- 偏差 30° → 点积 ≈ 0.866

所以"点积 ≥ 0.996" 就是"方向偏差 ≤ 5°"。调这个阈值就是调**判定严不严**。

## 3. 认识 UE 的几个基础概念

### 3.1 Actor 和 Component
- **Actor**：场景里能放的"东西"的基类（门、柱子、灯、摄像机……都是 Actor）。
- **Component**：Actor 的功能零件。一个门 Actor 可以有"静态网格体组件"（显示模型）、"碰撞组件"（阻挡玩家）等。
- 我们的谜题管理器 `APerspectivePuzzleManager` 也是一个 Actor，它的根组件是 `UArrowComponent`（编辑器里显示一个箭头，方便定位）。

### 3.2 蓝图 vs C++
| | 蓝图 Blueprint | C++ |
|---|---|---|
| 是什么 | 节点连线，可视化编程 | 写代码 |
| 上手 | 快，适合逻辑/UI | 慢，但性能好、能碰引擎底层 |
| 本项目用法 | 事件接线（解密成功、开门）、材质参数 | 检测算法、发光控制 |

本项目是**混合**：核心检测算法写 C++（`PerspectivePuzzleManager`），事件触发、开门动画用蓝图。这是 UE 项目最常见的组合。

### 3.3 UCLASS / UPROPERTY / UFUNCTION 是什么

C++ 类和引擎"对话"靠这些宏：

```cpp
UCLASS()                        // 告诉引擎：这是 UE 类，可以放进场景
class CPP1_API APerspectivePuzzleManager : public AActor
{
    UPROPERTY(EditAnywhere)     // 告诉引擎：这个变量可以在细节面板改
    float CameraHeightOffset = 160.0f;

    UFUNCTION(BlueprintCallable) // 告诉引擎：这个函数可以给蓝图调用
    void ResetPuzzle();
};
```

- `UCLASS` → 这个类被引擎识别。
- `UPROPERTY` → 这个变量能被引擎序列化（保存/加载）、能在细节面板编辑、能被蓝图访问。
- `UFUNCTION` → 这个函数能被蓝图调用，或作为"蓝图事件"被实现。

### 3.4 UHT 和编译

UE 的 C++ 编译分两层：
1. **UHT（Unreal Header Tool）**：扫描 `UCLASS/UPROPERTY/UFUNCTION`，生成 `.generated.h` 等文件。
2. **UBT（Unreal Build Tool）+ 编译器**：真正编译成 DLL。

**常见坑**：改了头文件但 UHT 没重新跑，就会报"无法打开 generated.h"或"未找到某函数定义"。清理 `Intermediate/Build/Win64/UnrealEditor/Inc/CPP1` 能强制 UHT 重新生成。

## 5. 第一步：图案的制作与导入

### 5.1 准备图案源文件
需要一个**背景透明**的图案图片。本项目用五角星 + 圆环，用 SVG 精确画好坐标，再导出 PNG。

**SVG 关键点**（`star_circle_pattern.svg`）：
- 五角星用 `<polygon>` 指定 10 个顶点坐标，保证五角星标准。
- 圆环用两个 `<circle>`（外粗圈 + 内细圈），颜色金色 `#c8962e` / `#ffdb4d`。
- 背景 `#0d0d14` 深色，最终做成透明背景贴图。

### 5.2 导入 UE
1. 把 PNG 拖进内容浏览器的 `Materials` 文件夹（或任意文件夹）。
2. UE 自动生成一个贴图资产。选中它 → 细节面板检查：
   - **Texture Type** = `Diffuse`（漫反射）或 `User Interface` 2D（看用途）。
   - **sRGB** = 勾选（普通颜色贴图）。
   - 如果背景没透明：需要在 PS/画图里抠掉背景，或用 UE 的 `Premultiplied Alpha` 设置。

> **注意**：图案要能在材质里用 `TexCoord` 分割，所以**必须是整块大图**，不要先切成两半——切割在材质里做（见下一步）。

## 6. 第二步：材质与图案分割

### 6.1 为什么"分割"要在材质里做
我们不想把贴图物理切成两张图（那样多了就乱）。UE 材质里可以用 **UV 偏移/缩放** 让同一张贴图只显示一部分。这样图案要分成多少块，都不用重新做图。

### 6.2 核心概念：UV 坐标
每张 2D 贴图在材质里都有一对 UV 坐标：
- U（横轴）：0~1，从左到右。
- V（纵轴）：0~1，从下到上。

一个 UV 节点 `TexCoord` 默认让贴图完整显示（UV 从 0~1）。对 UV 做数学变换，就能**只取贴图的一部分**。

### 6.3 图案分割的节点连接（重点）
我们要把贴图**上下分两半**，需要把 V 轴做"偏移 + 缩放"：

```
TexCoord (UV 0~1)
   │
   ▼
Multiply (乘) ←─ UVTiling 参数：控制缩放
   │
   ▼
Add (加)    ←─ UVOffset 参数：控制偏移
   │
   ▼
TextureSample 的 UVs 输入   ← 贴图取样的 UV 就用处理后的
```

**数学解释**：
- `UV = 原始UV × Tiling + Offset`
- **上半**：`Tiling = (1, 0.5)`（V 方向缩一半，只取上半），`Offset = (0, 0)`。
- **下半**：`Tiling = (1, 0.5)`，`Offset = (0, 0.5)`（从 V=0.5 开始取，取下半）。

### 6.4 材质实例（Material Instance）
**母材质（M_BStar）** 里把 `UVTiling` 和 `UVOffset` 声明为**向量参数（VectorParameter）**。然后创建**两个材质实例**：

| 材质实例 | UVTiling | UVOffset | 显示的部分 |
|---|---|---|---|
| `MI_Star_Top` | (1, 0.5) | (0, 0) | 上半（星的上半+圆环上半） |
| `MI_Star_Bot` | (1, 0.5) | (0, 0.5) | 下半 |

**为什么分两步**：
- **母材质**管"逻辑"（怎么拼、参数有哪些），写一次。
- **材质实例**管"数值"（具体取哪块），随便复制，改数值即可。要分 4 块、9 块都行，各做一个实例改参数，**不用重做贴图**。

> **提示**：本材质是 **Unlit**（不受光照）模型，配 **Translucent Decal** 混合模式，用于地面/墙面贴画（见下一步）。

## 7. 第三步：场景摆放（Decal 贴画）

### 7.1 Decal 是什么
**Decal（贴花/贴画）** 是一个"贴"在物体表面的图案组件，会沿着表面弯曲贴合，像贴纸。非常适合把图案贴在柱子、墙面上。

### 7.2 操作步骤
1. 在关卡里添加一个 **Decal Actor**（`内容浏览器` 里搜 `DeferredDecal`，或右键放置）。
2. 把材质实例（`MI_Star_Top` / `MI_Star_Bot`）拖到 Decal 的 `Decal Material` 槽里。
3. 用**移动/旋转/缩放**工具把 Decal 摆到目标物体上：
   - 调整 `Decal Size`（`UDecalComponent` 的大小，本项目用如 (30, 110, 120)），让图案**只盖住柱子正面**，别蔓延到侧面/顶面。
   - 对准玩家视角方向。
4. 上下两块分别摆，**手动微调位置**，让它们在玩家正确视角下拼成完整图案。

> **为什么 Decal 必须手动摆**：图案对齐是视觉效果，引擎不知道你要拼成什么样，只能靠眼睛手动对。这也是本项目最重要的"手工活"。

### 7.3 两个碎片摆位的技巧
- 一个放**柱子**（近），一个放**墙**（远），拉开深度差，视差才明显。
- 站在最终判定点，边看边微调 Decal 位置，直到视野里完美拼合。
- 用 `DrawDebugCalibration`（C++ 里的调试绘制）看标定位置和目标方向，辅助对齐。

## 8. 第四步：检测逻辑（C++ Manager）

这是项目的灵魂：`APerspectivePuzzleManager`。下面按文件拆开讲。

### 8.1 头文件 `PerspectivePuzzleManager.h`

```cpp
// 单个碎片的标定数据：记住"标定时这个碎片在哪、离标定点多远的哪个方向"
USTRUCT(BlueprintType)
struct FCalibratedMarkPoint
{
    GENERATED_BODY()
    UPROPERTY(EditAnywhere, BlueprintReadWrite)
    AActor* FragmentActor = nullptr;   // 场景里的碎片 Actor
    FVector WorldLocation;             // 标定时碎片的世界坐标
    FVector TargetDirection;           // 从标定点指向碎片的单位方向
    float TargetDistance;              // 标定点到碎片的直线距离
};

UCLASS()
class CPP1_API APerspectivePuzzleManager : public AActor
{
    GENERATED_BODY()
public:
    APerspectivePuzzleManager();

    // === 拼图设置 ===
    UPROPERTY(EditAnywhere, Category = "Puzzle")
    TArray<AActor*> FragmentActors;    // 拖入所有碎片 Actor
    UPROPERTY(EditAnywhere, Category = "Puzzle")
    float CameraHeightOffset = 160.0f; // Manager 在地面，标定时抬到玩家眼睛高度
    UPROPERTY(EditAnywhere, Category = "Puzzle")
    FName GlowParameterName = TEXT("GlowIntensity"); // 发光材质参数名

    // === 检测参数 ===
    UPROPERTY(EditAnywhere, Category = "Detection")
    float DotProductThreshold = 0.996f;  // 方向容差 cos(5°)
    UPROPERTY(EditAnywhere, Category = "Detection")
    float ViewAngleThreshold = 0.996f;   // 视线容差（防低头）
    UPROPERTY(EditAnywhere, Category = "Detection")
    float DistanceTolerance = 50.0f;     // 距离容差
    UPROPERTY(EditAnywhere, Category = "Detection")
    float RequiredPassRate = 0.8f;       // 多少碎片通过算成功
    UPROPERTY(EditAnywhere, Category = "Detection")
    float HoldDuration = 1.5f;           // 需持续对齐多久
    UPROPERTY(EditAnywhere, Category = "Detection")
    float DetectionInterval = 0.1f;      // 检测频率

    // === 状态 ===
    UPROPERTY(BlueprintReadOnly, Category = "State")
    bool bIsSolved = false;              // 是否已解密
    UPROPERTY(BlueprintReadOnly, Category = "State")
    float SolveProgress = 0.0f;          // 对齐进度 0~1

    // === 可调用函数 ===
    UFUNCTION(BlueprintCallable, Category = "Puzzle", meta = (CallInEditor = "true"))
    void Calibrate();                    // 标定（编辑器里点按钮执行）
    UFUNCTION(BlueprintCallable, Category = "Puzzle")
    void ResetPuzzle();                  // 重置
    UFUNCTION(BlueprintCallable, Category = "Debug", meta = (CallInEditor = "true"))
    void DrawDebugCalibration(float Duration = 5.0f) const;

    // === 蓝图事件（在蓝图里实现）===
    UFUNCTION(BlueprintImplementableEvent, Category = "Events")
    void OnPuzzleSolved();               // 解密成功
    UFUNCTION(BlueprintImplementableEvent, Category = "Events")
    void OnViewAligned();                // 开始对齐
    UFUNCTION(BlueprintImplementableEvent, Category = "Events")
    void OnViewLost();                   // 失去对齐
    UFUNCTION(BlueprintImplementableEvent, Category = "Events")
    void OnProgressUpdated(float Progress); // 进度更新

protected:
    TArray<FCalibratedMarkPoint> CalibratedData; // 标定结果
    float HoldTimer = 0.0f;
    bool bWasAligned = false;
    mutable TObjectPtr<class APlayerController> CachedPC;
    FVector CalibratedOrigin;            // 标定原点（相机高度）
    FVector CalibratedViewTarget;        // 图案中心（视线检测参考点）
    FTimerHandle DetectionTimerHandle;
    void CheckPuzzle();
    UPROPERTY(Transient)
    TArray<UMaterialInstanceDynamic*> FragmentMaterials; // 缓存发光用材质
    void CacheFragmentMaterials();
};
```

**几个值得注意的设计**：
- `FCalibratedMarkPoint` 是一个**结构体**，把"一个碎片要记住的所有信息"打包。
- `FragmentActors` 是 `TArray<AActor*>`（**裸指针数组**）。这里用裸指针是因为引擎的反射系统对 `TObjectPtr` + 前向声明类型有坑（见踩坑记录）。
- `OnPuzzleSolved` 等是 `BlueprintImplementableEvent`：**C++ 只声明、不实现**，实现在蓝图里。C++ 负责"什么时候触发"，蓝图负责"触发后干什么"——解耦。

### 8.2 实现文件 `PerspectivePuzzleManager.cpp`

#### 8.2.1 标定 `Calibrate()` —— 记住"正确视角"

```cpp
void APerspectivePuzzleManager::Calibrate()
{
    CalibratedData.Empty();
    // 标定原点 = Manager 位置抬升到相机高度
    CalibratedOrigin = GetActorLocation() + FVector(0, 0, CameraHeightOffset);

    FVector CenterAccum = FVector::ZeroVector;
    int32 Count = 0;

    for (AActor* Actor : FragmentActors)
    {
        if (!Actor) continue;

        FCalibratedMarkPoint Point;
        Point.FragmentActor = Actor;
        Point.WorldLocation = Actor->GetActorLocation();

        FVector Dir = Point.WorldLocation - CalibratedOrigin;
        Point.TargetDistance = Dir.Size();            // 距离 = 向量长度
        Point.TargetDirection = Dir.GetSafeNormal();  // 方向 = 单位向量

        CalibratedData.Add(Point);
        CenterAccum += Point.WorldLocation;
        Count++;
    }

    // 图案中心 = 所有碎片的几何中心，作为视线检测的参考点
    CalibratedViewTarget = (Count > 0) ? CenterAccum / Count : CalibratedOrigin;
}
```

**原理**：标定 = 站在正确位置"拍照留念"。
- 把 Manager 放在地上，`CameraHeightOffset` 把它抬到玩家眼睛高度，得到标定原点。
- 对每个碎片，记录从原点到碎片的**方向（单位向量）**和**距离（标量）**。
- 图案中心是所有碎片位置的**平均值**（几何中心），用来做视线检测（后面防低头用）。

#### 8.2.2 缓存发光材质 `CacheFragmentMaterials()`

```cpp
void APerspectivePuzzleManager::CacheFragmentMaterials()
{
    FragmentMaterials.Empty();
    for (AActor* Actor : FragmentActors)
    {
        UMaterialInstanceDynamic* DynMat = nullptr;
        if (UDecalComponent* Decal = Actor->FindComponentByClass<UDecalComponent>())
        {
            // 把 Decal 的材质转成动态实例，运行时才能改发光参数
            if (UMaterialInterface* DecalMat = Decal->GetDecalMaterial())
            {
                DynMat = UMaterialInstanceDynamic::Create(DecalMat, Decal);
                Decal->SetDecalMaterial(DynMat);
            }
        }
        else if (UStaticMeshComponent* SM = Actor->FindComponentByClass<UStaticMeshComponent>())
        {
            DynMat = SM->CreateAndSetMaterialInstanceDynamic(0);
        }
        FragmentMaterials.Add(DynMat);
    }
}
```

**原理**：要在运行时改材质参数，必须用**动态材质实例**（`UMaterialInstanceDynamic`）。普通材质参数是"冻结"的，动态实例才能用代码 `SetScalarParameterValue` 实时改。

#### 8.2.3 核心检测 `CheckPuzzle()` —— 每 0.1 秒问一次"你站对了吗"

```cpp
void APerspectivePuzzleManager::CheckPuzzle()
{
    if (bIsSolved || CalibratedData.Num() == 0) return;

    APlayerController* PC = UGameplayStatics::GetPlayerController(GetWorld(), 0);
    if (!PC || !PC->PlayerCameraManager) return;

    FVector CamLoc; FRotator CamRot;
    PC->GetPlayerViewPoint(CamLoc, CamRot);       // 拿到玩家相机位置和朝向
    FVector CamForward = CamRot.Vector();          // 相机朝向单位向量

    // —— 视线检测：你是否看向图案中心（防低头作弊）——
    FVector ViewTargetDir = (CalibratedViewTarget - CalibratedOrigin).GetSafeNormal();
    float ViewDot = FVector::DotProduct(CamForward, ViewTargetDir);
    bool bViewMatch = (ViewDot >= ViewAngleThreshold);

    int32 PassCount = 0;
    for (const auto& Point : CalibratedData)
    {
        FVector ToFragment = Point.WorldLocation - CamLoc;
        float CurrentDist = ToFragment.Size();
        FVector CurrentDir = ToFragment.GetSafeNormal();

        // 位置检测：相机到碎片的方向/距离 是否匹配标定值
        float Dot = FVector::DotProduct(CurrentDir, Point.TargetDirection);
        float DistDiff = FMath::Abs(CurrentDist - Point.TargetDistance);
        if (Dot >= DotProductThreshold && DistDiff <= DistanceTolerance)
            PassCount++;
    }

    // 位置对齐 + 视线对准 都满足才算对齐
    float Rate = (float)PassCount / (float)CalibratedData.Num();
    bool bAlignedNow = (Rate >= RequiredPassRate) && bViewMatch;

    if (bAlignedNow)
    {
        if (!bWasAligned) OnViewAligned();       // 刚对齐，触发一次

        HoldTimer += DetectionInterval;
        SolveProgress = FMath::Clamp(HoldTimer / HoldDuration, 0.0f, 1.0f);
        OnProgressUpdated(SolveProgress);        // 进度给蓝图

        if (HoldTimer >= HoldDuration)           // 持续够 2 秒了
        {
            bIsSolved = true;
            SolveProgress = 1.0f;
            OnProgressUpdated(1.0f);
            OnPuzzleSolved();                    // ★ 触发成功事件
            GetWorldTimerManager().ClearTimer(DetectionTimerHandle); // 停止检测
        }
    }
    else
    {
        if (bWasAligned) OnViewLost();           // 刚失焦，触发一次
        HoldTimer = 0.0f;
        SolveProgress = 0.0f;
    }

    // —— 发光：对齐时随进度增强，失焦时归零 ——
    if (GlowParameterName != NAME_None)
    {
        float GlowValue = bAlignedNow ? SolveProgress : 0.0f;
        for (UMaterialInstanceDynamic* DynMat : FragmentMaterials)
            if (DynMat) DynMat->SetScalarParameterValue(GlowParameterName, GlowValue);
    }

    bWasAligned = bAlignedNow;
}
```

**检测逻辑逐句拆**：
1. **取相机**：`GetPlayerViewPoint` 得到玩家眼睛在世界里的位置 `CamLoc` 和朝向 `CamRot`。
2. **视线检测**：看相机朝向和"标定点→图案中心"方向的点积。防止玩家低头看脚还能触发。
3. **位置检测**：对**每个碎片**，算相机→碎片的当前方向/距离，和标定值比点积、比距离差。
4. **通过率**：`Rate = 通过的碎片 / 总碎片`，达到 `RequiredPassRate` 且视线通过 → 对齐。
5. **计时**：对齐就累加 `HoldTimer`，否则清零。满 `HoldDuration` 才算真正解密——**防止一晃而过**。
6. **发光**：每帧把 `GlowValue`（对齐进度）写进材质参数 `GlowIntensity`，实现"越对越亮"。

**为什么要"持续 2 秒"**：如果一进判定区就触发，玩家随便路过就解开了。要求持续保持，才说明是"认真站在那看图案"。

### 8.3 定时器在哪开的

```cpp
void APerspectivePuzzleManager::BeginPlay()
{
    Super::BeginPlay();
    Calibrate();                // 先标定
    CacheFragmentMaterials();   // 缓存材质
    ResetPuzzle();              // 里面会开定时器
    DrawDebugCalibration(100000.0f); // 调试用：一直显示标定位置
}

void APerspectivePuzzleManager::ResetPuzzle()
{
    bIsSolved = false;
    bWasAligned = false;
    HoldTimer = 0.0f;
    SolveProgress = 0.0f;
    GetWorldTimerManager().ClearTimer(DetectionTimerHandle);
    GetWorldTimerManager().SetTimer(
        DetectionTimerHandle, this, &APerspectivePuzzleManager::CheckPuzzle,
        DetectionInterval, true);   // 每 DetectionInterval 秒，循环调用 CheckPuzzle
}
```

用**定时器**而不是每帧 Tick，是因为没必要每帧（0.016s）检测，0.1 秒一次足够，省性能。

## 9. 第五步：检测参数详解与调优

所有参数都在细节面板的 **Detection** 分类下，拖滑块即可，**不用重新编译**。

| 参数 | 默认 | 本项目最终 | 含义 | 调大/调小的影响 |
|---|---|---|---|---|
| `DotProductThreshold` | 0.996 | **0.98** | 位置方向容差（cos 角度） | 调小=站偏一点也算，调大=必须站很准 |
| `DistanceTolerance` | 50 | **100** | 距离容差（世界单位） | 调大=前后差一点也算 |
| `ViewAngleThreshold` | 0.996 | 约 0.98~0.99 | 视线容差 | **别乱调小**，会放低头作弊 |
| `RequiredPassRate` | 0.8 | 0.8 | 多少碎片通过算对齐 | 碎片多时可调低，容错 |
| `HoldDuration` | 1.5 | **2.0** | 持续对齐秒数 | 调大=更严格 |
| `DetectionInterval` | 0.1 | 0.1 | 检测频率 | 不用动 |

**调优口诀**：
- "站对了还是触发不了" → 调大容差（`DotProductThreshold` 调小、`DistanceTolerance` 调大）。
- "离很远也能触发" → 调严。
- **视线检测（ViewAngleThreshold）最后动**：它专门防"低头还拼图"，太松会让之前的 bug 回来。
- 一次只改一个参数、测试一次，别一次全调。

## 10. 第六步：发光反馈（Emissive + Bloom）

### 10.1 为什么接 Emissive 而不是 BaseColor
- 把发光接到 **BaseColor**（基础色）→ 图案颜色被调亮、**发白/漂洗**，不是"发光"。
- 接到 **EmissiveColor**（自发光）→ 图案**颜色不变**，只是"自己发光"，像光源。

### 10.2 材质侧改动（M_BStar）
**发光链**：

```
GlowIntensity (标量参数, 默认0, 由 C++ 每帧写入)
   │ × 6 (发光强度倍数)
   ▼
Multiply
   │
   ▼
Add (+ 1)          ← 保证 GlowIntensity=0 时图案亮度 = 贴图×1（正常）
   │
   ▼
Multiply ── 贴图颜色 TextureSample.RGB
   │
   ▼
EmissiveColor
```

- `GlowIntensity = 0` → Emissive = 贴图 × 1 → **正常图案**。
- `GlowIntensity = 1` → Emissive = 贴图 × (1+6) = 贴图 × 7 → **强发光**。
- 材质设为 **Unlit**（不受光照影响），图案永远亮。

### 10.3 光晕（Bloom）—— 发光的关键
只有自发光会显得"亮"，要加 **Bloom（泛光/光晕）** 才有"发光扩散"感：
1. 场景放一个 **PostProcessVolume**，勾选 **Unbound**（影响整个场景）。
2. 细节面板 → **Bloom → Bloom Intensity** → **1.5 ~ 3**。
3. 发光强的地方会带一圈光晕，就是真实的"发光"。

### 10.4 时间线
- **对齐中**：`GlowIntensity` 0→1，发光平滑增强（对应 SolveProgress）。
- **失焦**：`GlowIntensity` 归 0，发光熄灭。

## 11. 第七步：开门机关

### 11.1 事件接线
`BP_PuzzleManager` 蓝图里，在 `OnPuzzleSolved` 事件后接上门：
```
OnPuzzleSolved (C++ 触发) ──▶ 打印"解密成功" ──▶ 获取场景里的门 ──▶ 调用门的 OpenDoor
```

获取门的方式：用 `GetActorOfClass`（按类找场景里的门）→ `Cast to BP_damage_door` → 调用 `OpenDoor`。

### 11.2 门蓝图（BP_damage_door）里的开门动画

最终结构（用 Timeline 关键帧 + Lerp 绝对插值）：

```
OpenDoor (自定义事件)
   │
   ▼
DoorAnim.Play (Timeline 播放)
   │
   └─▶ Update 每帧：
        Timeline.轨道0 (0→1)
             │
             ▼
        Lerp (A=90, B=180, Alpha=轨道值)   ← 绝对插值，不累积
             │
             ▼
        SetRelativeRotation(door)           ← 设置门板相对旋转
```

- Timeline 轨道 0~1 秒，值 **0→1**。
- `Lerp(90 → 180)`：门板从 **90°（关闭）→ 180°（打开）**。
- 门板组件 `door` 的**关闭姿态本身是 Yaw=90°**（Fab 门模型自带偏转），所以开门终点是 180°。

### 11.3 为什么这里必须用 Lerp，不能"当前角度 + 增量"

**错误做法**（一开始踩的坑）：
```
门当前Yaw + Progress×90   → 每帧都读门"当前"角度再往上加
```
因为 `SetRelativeRotation` 每帧把门改大了，下一帧读到的"当前角度"就更大，增量不断累积 → **疯狂旋转**。

**正确做法**：**Lerp 绝对插值**。每一帧都从固定的 90° 直接插到 180°，输出跟门当前状态无关，**永远不会累积**。

> 通用原则：**动画里要做"从起点平滑变到终点"，优先用绝对插值（Lerp / FInterp），别用"当前值每帧累加"**，后者是旋转累积 bug 的根源。

### 11.4 方向反了怎么办
把 Lerp 改成 `A=90, B=0`（或 A=-90, B=0），看门往哪边开。数值都是世界角度，按视觉效果微调。

## 12. 常见问题与踩坑记录

### 12.1 C++ 编译类

| 症状 | 原因 | 解决 |
|---|---|---|
| 中文注释乱码 | 文件没存 UTF-8 带 BOM | 用 `UTF-8 with BOM`（utf-8-sig）保存 |
| 双 BOM 破坏 UHT | 加了两次 BOM | 只留一个 BOM |
| `TArray<TObjectPtr<T>>` 报 `StaticAssert` 模板错误 | `TObjectPtr` + 前向声明类型 | 改用裸指针数组 `TArray<T*>` |
| "无法打开 generated.h" / "未找到 XX 函数定义" | UHT 没重新生成 | 清 `Intermediate/Build/Win64/UnrealEditor/Inc/CPP1` |
| "Unable to build while Live Coding is active" | Live Coding 占用 | 关编辑器，或用 Ctrl+Alt+F11 |
| `CreateDynamicMaterialInstance(0)` 参数报错 | 5.8 签名变了 | 用 `GetDecalMaterial() + UMaterialInstanceDynamic::Create + SetDecalMaterial()` |

### 12.2 检测不触发类

| 症状 | 原因 | 解决 |
|---|---|---|
| 站对了不触发（Dot 只有 0.86） | 相机高度和 Manager 高度不一致 | 设 `CameraHeightOffset` = 玩家眼睛高度 |
| 低头也触发 | 没做视线检测 | 加 `ViewAngleThreshold`（已内置） |
| 加了视线检测后不触发 | 视线指单个碎片，两个碎片对不准 | 视线改指**所有碎片几何中心**（已内置） |
| 触发太严格/太松 | 阈值不合适 | 调 Detection 面板参数（见第 9 节） |

### 12.3 视觉/材质类

| 症状 | 原因 | 解决 |
|---|---|---|
| 图案全黑 | 材质没连 Opacity 或混合模式不对 | Decal 用 Translucent 混合、确认 Opacity |
| 发光像漂白 | 接到 BaseColor 了 | 改接 **EmissiveColor** |
| 发光不明显 | 没 Bloom | PostProcessVolume 开 Bloom，强度 1.5~3 |
| Decal 蔓延到柱子顶面 | Decal Size 太大 | 缩小 Decal Size，只盖正面 |

### 12.4 门动画类

| 症状 | 原因 | 解决 |
|---|---|---|
| 开门瞬间跳一下再动 | 动画起点和门初始姿态不一致 | 用绝对插值，起点 = 关闭姿态角度 |
| 疯狂旋转 | 每帧"当前角度+增量"累积 | 改 **Lerp 绝对插值**（见第 11 节） |

## 14. 扩展思路

1. **更多碎片**：图案切成 4 块、9 块 → 复制材质实例改 UVTiling/UVOffset，Decal 多摆几个，`RequiredPassRate` 相应调整。
2. **碎片逐个点亮**：现在所有碎片同步发光。可以改成：对每个碎片单独维护 `GlowValue`，让它们随"各自检测通过"逐个点亮，更有仪式感。
3. **多扇门 / 其他机关**：`OnPuzzleSolved` 是蓝图事件，后面想连什么（开门、播动画、出怪、音效）都在蓝图上接即可。
4. **多关/多谜题**：场景里放多个 Manager，各自有 `FragmentActors` 和判定参数，互不影响。
5. **存档**：`bIsSolved` 已经 BlueprintReadOnly，可以接一个存档系统，解密后下次进来门保持开。
6. **Tag 找门**：现在用 `GetActorOfClass`（场景只有一个门时够用）；多门时给门加 **Tag**，按 Tag 查找更稳。
