# 透视拼接谜题实现笔记

环境：UE 5.8、C++ 项目。这个实现只解决一件事：场景里的多个图案碎片在特定观察点拼合时，如何稳定地判定玩家真的站到了那个点，并且在看图案。

完整代码在 `Source/CPP1`；本文记录场景配置、判定方式和几个实际踩到的问题。

## 方案选择

碎片显示和判定是两件事。

显示上，碎片使用 Deferred Decal 手动摆在柱子、墙面等不同深度的表面。手动摆放不可避免：是否“拼得像”是视觉问题，不能由检测代码自动解决。

判定上，没有使用屏幕空间投影或画面相似度。当前方案在标定时记录每个碎片相对观察点的方向和距离；运行时重新计算相机到碎片的方向和距离，再做比较。优点是简单，不依赖分辨率、FOV 或贴图内容。代价是标定点与玩家相机高度必须对齐。

## 场景和标定

1. 用同一张图案贴图创建母材质和材质实例。
2. 用 UVTiling/UVOffset 让不同实例显示贴图的不同区域。
3. 将实例分别赋给 Decal，摆在不同深度的物体表面。
4. 把 `BP_PuzzleManager` 放到目标观察位置；`CameraHeightOffset` 设为相机高度。
5. 将全部碎片 Actor 填入 `FragmentActors`，点击 `Calibrate`。

标定时，代码对每个碎片保存：

```text
TargetDirection = Normalize(FragmentLocation - CalibratedOrigin)
TargetDistance  = Length(FragmentLocation - CalibratedOrigin)
```

同时计算全部碎片位置的平均值 `CalibratedViewTarget`，作为视线检测目标。

## 判定

每 `DetectionInterval` 秒执行一次 `CheckPuzzle()`。

### 位置

对每个碎片：

```text
CurrentDirection = Normalize(FragmentLocation - CameraLocation)
CurrentDistance  = Length(FragmentLocation - CameraLocation)

DirectionDot = Dot(CurrentDirection, TargetDirection)
DistanceDiff = Abs(CurrentDistance - TargetDistance)
```

当 `DirectionDot >= DotProductThreshold` 且 `DistanceDiff <= DistanceTolerance` 时，这个碎片通过。

方向和距离需要一起使用。只比距离不能区分方位：观察点前方五米和左侧五米到目标的距离可能相同，视角却不同。点积比较的是“当前相机位置到某个碎片的连线方向”与“标定点到该碎片的连线方向”，它不读取玩家相机的朝向。

所有碎片检测结束后：

```text
PassRate = PassCount / FragmentCount
PositionMatch = PassRate >= RequiredPassRate
```

### 视线

位置检测解决不了“玩家站对了但低头看地”的情况。最初版本没有这一层，低头仍会触发。

当前代码将相机前向向量与以下方向比较：

```text
ViewTargetDirection = Normalize(CalibratedViewTarget - CalibratedOrigin)
ViewDot = Dot(CameraForward, ViewTargetDirection)
```

`ViewDot >= ViewAngleThreshold` 才算视线通过。目标取碎片几何中心，不取某一个碎片；多个碎片无法被视线同时逐个对准，但玩家应当看向拼合后的图案中心。

最终状态：

```text
Aligned = PositionMatch && ViewMatch
```

### 持续时间

对齐时累积 `HoldTimer`，失去对齐就清零。`SolveProgress` 是 `HoldTimer / HoldDuration`，用于蓝图/UI/发光。达到 `HoldDuration` 后调用 `OnPuzzleSolved()` 并停止检测定时器。

## 材质与发光

图案没有物理切图。母材质对 TexCoord 做：

```text
UV = TexCoord * UVTiling + UVOffset
```

上半实例：`UVTiling=(1, 0.5)`、`UVOffset=(0, 0)`；下半实例：`UVTiling=(1, 0.5)`、`UVOffset=(0, 0.5)`。

发光参数为 `GlowIntensity`。C++ 在对齐阶段向每个动态材质实例写入 `SolveProgress`。材质应该将该参数用于 EmissiveColor；叠到 BaseColor 只会把颜色推白。Bloom 负责把高亮扩散成光晕。

## 蓝图机关

`OnPuzzleSolved` 是 `BlueprintImplementableEvent`。检测代码不包含关卡机关；在 `BP_PuzzleManager` 中实现该事件即可。

示例里，蓝图用 `GetActorOfClass → Cast to BP_damage_door → OpenDoor` 调门的开门事件。

门动画使用 Timeline 的 0→1 轨道驱动 `Lerp(90, 180, Alpha)`，再写入门板相对 Yaw。不要每帧做“当前角度 + 增量”：当前角度已经被上一帧修改，增量会累积，门会持续旋转。

## 调参记录

| 参数 | 使用值 | 备注 |
|---|---:|---|
| `DotProductThreshold` | `0.98` | 原始 `0.996` 对站位偏移过于敏感 |
| `DistanceTolerance` | `100` | 原始 `50` 手感偏硬 |
| `ViewAngleThreshold` | `0.98 ~ 0.99` | 继续降低会放宽低头/偏头判定 |
| `RequiredPassRate` | `0.8` | 碎片数增加时可保留少量容错 |
| `HoldDuration` | `2.0` | 用作发光充能和防误触发 |
| `DetectionInterval` | `0.1` | 不需要 Tick 级频率 |

## 已遇到的问题

| 问题 | 处理 |
|---|---|
| 中文注释乱码、UHT 连锁报错 | 文件统一为 UTF-8 with BOM；避免双 BOM |
| `generated.h` 未生成 | 清理 `Intermediate/Build/Win64/UnrealEditor/Inc/CPP1` 后重编译 |
| Live Coding 阻止命令行构建 | 关闭 Live Coding 或通过编辑器编译 |
| `TArray<TObjectPtr<T>>` 与前向声明触发静态断言 | 这里改用裸指针数组 |
| Decal 图案延伸到柱顶 | 缩小 Decal Size，只让投影盒覆盖正面 |
| 低头仍触发 | 加图案中心视线检测 |
| 发光像漂白 | 从 BaseColor 改接 EmissiveColor，并启用 Bloom |
| 门不停旋转 | 用固定起点/终点的 Lerp，禁止每帧累加当前角度 |

## 可继续改的地方

- 每个碎片单独记录对齐状态，做逐块点亮。
- 多门场景改用 Actor Tag，而不是 `GetActorOfClass`。
- 保存 `bIsSolved`，重新加载关卡后保留机关状态。
- 如果需要更严格的视觉一致性，再考虑屏幕空间投影检测；当前实现不检查碎片在屏幕上的实际重叠。
